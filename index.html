Project 01 / 03

途泊 · 龙虾实验助手

把「龙虾实验助手」从独立页面升级为实验全程随时可调的全局浮窗 AI 助手，打通真实实验数据回传链路——「一句话进实验 → 自动配置 → 结果实时回传」。

Role
实验组成员 · 独立承担接入与功能改进
Timeline
2026.03 — 至今
Team
途泊项目 · 实验组协作
Users
通信实验场景 20+ 类 · 5 个实验组试用

Overview

全局浮窗 AI 助手 + 一句话进实验 + 实验数据实时回传，入口操作由 4~5 步缩减至 1~2 步。我独立负责产品交互、数据闭环与 Prompt 迭代。

Challenge

原实验入口需 4~5 步、助手只能独立页面使用，实验过程中无法随时提问与配置。核心挑战是把「配置 → 提问 → 结果」的成本降到最低，并打通真实数据回传，让 AI 从「能回答问题」进化为「理解实验行为」。

Solution

将助手升级为实验全程可调用的全局浮窗，用一句话进实验替代 4~5 步配置，并打通「实验箱 → 平台」的数据实时回传链路，形成「请求 → 配置 → 结果」的完整闭环。

Impact

实验入口步骤由 4~5 步缩减至 1~2 步，场景识别由 15+ 拓展至 20+；5 个实验组试用、30+ 条反馈驱动多轮 Prompt 与交互迭代，真实数据回传形成平台闭环。

Reflection

交互优化的本质是缩短用户到达目标的路径；数据闭环让 AI「越用越准」。Prompt 优化应围绕「回答边界 + 交互流程」设计——好产品，就是让复杂消失。

途泊 · 龙虾实验助手

2026.03 — 至今 · 实验组成员 | 独立承担龙虾的接入 & 功能改进

0~0 → 0~0实验入口步骤
0实验场景识别
0体验反馈迭代
0场景拓展

01 · Overview

把「龙虾实验助手」从独立页面升级为实验全程可随时调用的全局浮窗 AI 助手，并打通真实实验数据回传链路，实现「一句话进实验 → 自动配置 → 结果实时回传」的完整闭环。

我的角色：实验组成员，独立承担龙虾的接入与功能改进，负责产品交互、数据闭环与 Prompt 迭代。

02 · Problem

  • 入口繁琐：原实验入口操作需 4~5 步，平台使用门槛高、上手成本大。
  • 调用不便：助手为独立页面，实验过程中无法随时提问、配置与跳转。
  • 数据断流：实验结果分散在实验箱，难以回传平台，无法沉淀形成数据闭环。

03 · Research

梳理平台全部实验流程，将自然语言场景归纳为 20+ 类通信实验；联系专业内 5 个实验组试用并收集 30+ 条体验反馈，定位高频操作路径与使用卡点。

20+实验场景归纳 5个实验组试用 30+条体验反馈

04 · Thinking

  • 为什么是全局浮窗？实验是连续过程，助理应随时在侧，而不是打断流程跳转独立页面。
  • 为什么用自然语言入口？一次表达能替代 4~5 步配置，把交互成本降到最低。
  • 为什么打通数据回传？只有真实数据沉淀，AI 才能从「能回答问题」进化为「理解实验行为」。

05 · Solution

全局浮窗 AI 助手 + 一句话进实验 + 实验数据实时回传 + 围绕回答边界的多轮 Prompt 优化。

06 · Architecture

一句话指令→ 意图识别
20+ 场景→ 自动配置→ 下发实验箱 / 仿真→ 数据实时回传→ 平台沉淀

技术栈：FastAPI / OpenClaw / Prompt Engineering / Python，产品原型使用 Figma 完成。

07 · Workflow

一句话进实验 → 自动配置 → 结果实时回传。自然语言识别出 20+ 类通信实验场景，一键跳转进入对应实验；与第三方厂商协同打通实验箱数据回传链路，推动 IQ 参数等真实实验数据实时回传平台。

08 · Result

  • 交互优化：实验入口操作由 4~5 步缩减至 1~2 步，使用门槛显著降低。
  • 数据闭环：IQ 参数等真实实验数据实时回传平台；实验场景识别由 15+ 拓展至 20+。
  • 手册与迭代：自主撰写平台使用手册，5 个实验组试用、30+ 条反馈驱动多轮 Prompt 与交互迭代。

09 · Reflection

交互优化的本质是缩短用户到达目标的路径；数据闭环让 AI「越用越准」；Prompt 优化应围绕「回答边界 + 交互流程」设计，而不是堆叠指令。这次经历让我更笃信：好产品，就是让复杂消失。

基于深度学习的人机对战模型

五子棋 AI 对战系统 · 项目负责人 | 方案设计 + 工程实现

3 阶段混合决策策略
Self-Play持续生成棋局
DeepSeek高质量棋谱辅助
PyTorch深度网络训练

01 · Overview

用「规则引擎 + 深度网络 + DeepSeek」三阶段混合决策框架，把规则、网络与大模型协同为统一决策流程，解决自博弈训练的冷启动问题。

我的角色：项目负责人，负责方案设计 + 工程实现，全程独立推进。

02 · Problem

  • 冷启动慢：纯自博弈训练初期棋局数据质量不足、策略单一，模型难以收敛。
  • 数据成本高：不依赖海量人工棋谱的前提下，需要快速生成高质量训练样本。

03 · Research

自主调研 AlphaZero、Leela Zero 等自博弈思路及主流棋类 AI 产品，分析冷启动阶段的数据瓶颈，确定「规则兜底 + 网络评估 + 大模型增强」的混合思路。

AlphaZero / Leela Zero自博弈思路调研 主流棋类 AI产品分析

04 · Thinking

  • 规则引擎：擅长必胜、必防等确定局面，但天花板低。
  • 深度网络：能泛化复杂局面，但需要高质量训练数据。
  • DeepSeek：能生成高质量棋谱，但不适合实时决策。
  • 结论：三者按局面复杂度分工，比任何单一方案收敛更快、样本质量更高。

05 · Solution

三阶段混合决策：规则引擎快速过滤必胜、必防局面 → 深度网络完成棋局价值评估 → DeepSeek 在复杂局面提供策略建议与高质量棋谱，生成更高质量的训练样本。

06 · Architecture

棋局输入→ 规则引擎
必胜 / 必防过滤→ 深度网络
价值评估→ DeepSeek
复杂局面建议→ 标准落子

PyTorch 深度网络训练管线，基于新增高质量棋局持续更新训练集。

07 · Workflow

持续训练管线：高质量棋局 → 更新训练集 → 模型棋局判断能力与攻防策略持续优化；面向棋局分析场景设计 Prompt，约束模型输出标准化落子建议及策略解释，提升生成训练数据的一致性和可用性。

08 · Result

  • 三阶段框架落地：规则、网络与大模型协同为统一决策流程。
  • 高质量训练样本：Self-Play + DeepSeek 棋谱持续供给，训练集质量显著提升。
  • 持续优化：模型棋局判断能力与攻防策略随训练集更新不断进化。

09 · Reflection

把算法问题当作产品问题拆解：先用「最可靠」的规则兜底，再用「最聪明」的大模型增强；大模型的工程价值不在于生成，而在于可控约束下稳定供给高质量数据。

01 · Overview

从 0 到 1 负责校内辩论赛事的全流程策划与运营，统筹 10+ 人工作小组，服务百名选手与超千名观众。

我的角色：赛事负责人，全程负责赛事策划、赛程安排、团队分工与现场执行。

02 · Problem

  • 从无到有：赛制、赛程、裁判、宣传、现场执行环环相扣，流程复杂度高。
  • 多场次滚动：十余场赛事连续举办，需要可复用的组织方法，避免重复踩坑。

03 · Research

梳理赛事全流程节点，复盘每场赛事的卡点，将经验沉淀为可复用的执行清单与分工模板。

10+场赛事复盘 全流程节点梳理

04 · Thinking

  • 为什么流程化 + 清单化？降低多场次执行成本，把经验固化下来。
  • 为什么小组分工？职责明确才能保证现场零混乱。
  • 为什么重视宣传运营？赛事影响力的提升，源于持续的内容与节奏运营。

05 · Solution

设计赛事流程与规则 + 建立可复用执行清单 + 统筹 10+ 人工作小组 + 宣传与运营扩大赛事影响力。

06 · Architecture

赛事策划→ 规则与赛程→ 团队分工→ 宣传运营→ 现场执行→ 复盘沉淀

可复用的执行清单贯穿全程，保障十余场赛事稳定落地。

07 · Workflow

赛前：赛事策划 + 规则赛程 + 团队分工；赛时：现场执行与调度；赛后：复盘沉淀可复用执行清单。

08 · Result

  • 规模：累计组织校内赛事 10+ 场，参与成员 100+、观众人次 1000+。
  • 影响力：通过宣传与运营，单场观众规模提升至百人级。
  • 方法沉淀：建立可复用执行清单，多场赛事零重大失误落地。

09 · Reflection

赛事运营的本质是项目管理：用流程把不确定性降到最低，用分工把复杂度摊开，用复盘把经验固化。这些方法与产品项目的推进逻辑完全相通。
